# SkyRoute AI 自主研究与协作

五个模块各自完成研究、选型、设计与验证，再通过共享仓库持续融合。每位成员的 AI 都有本模块的技术决策权，可以交付完整方案，无需等待 ZQO 的架构稿或其他成员回复。ZQO 主责空域更新与版本一致性，兼顾架构整合；总体架构由各模块的输入输出和研究结论逐步形成。

## AI 如何自行作出技术决定

1. **确定约束。** 以用户确定的项目范围、课程要求、共同语义和现有证据为依据，先识别必须满足的条件。
2. **研究并比较。** 对影响设计的重要选择查阅论文、官方文档或可核查资料，比较适用候选；保留具体来源及版本条件。
3. **直接选择并完成。** AI 给出结论和理由，继续模型、图表、伪代码、模拟或推演。数据库、算法细节、索引、参数及验证方法等范围内的技术选择，无需逐项请成员或 ZQO 批准。
4. **记录证据和不确定性。** 无实测依据的参数标为模拟设定；风险代理与真实概率分开。证据不足时采用有适用边界的暂定选择，给出验证办法，继续完成该假设下的方案。
5. **按新证据修订。** 新成果证明当前方案不适用时，记录原因、替代方案和影响；兼容且证据充分的现有方案可以保留。

重要决定记录在自己的模块文档，可用 `LQ-D1` 等编号。一条记录说明：问题、候选、选择、依据、假设、验证、受影响文件及采用范围。状态用“本模块已采用”“暂定”或“已替代”；跨模块验证完成后说明核对的提交及结果。成员姓名不构成技术决定的优先级。

## 发现跨模块差异时直接推进

| 差异类型 | 当前 AI 的处理方式 |
| --- | --- |
| 缺少其他模块成果 | 补齐本模块所需的最小输入和模拟样例，完成自己的论证与验证；记录后续替换位置 |
| 字段名、封装或可转换的表达差异 | 添加映射或适配，检查转换前后的含义和结果，直接提交兼容修订 |
| 两种技术路线都满足约束 | 对照相同条件比较证据、复杂度和成本，选择更适合本项目的方案；证据接近时优先保留已兼容的方案 |
| 共同语义需要改变 | 读取受影响的已提交成果，补充迁移办法及检查，再更新共同约定和相关说明；任何正在工作的 agent 均可执行，无需等待负责人签字 |
| 暂时无法证明新语义兼容 | 保留现有基线，将新方案作为有版本的备选；完成当前基线下的交付，把尚未证明的局部结论明确列出 |

共同约定改变时，已存在的受影响成果必须有检查记录；尚未产生的成果只声明新旧约定与兼容方式，不能声称已验证。破坏兼容性的变更在迁移与必要检查完成前保留为备选。若发现现有基线本身违反已知硬约束，应标记受影响结论失效并修正，不能因保留基线而忽略错误。

执行修订的 AI 可以核对其他模块的已提交内容，并在自己的记录中写明检查对象和结果。复核无需等待对方在线；不得代写其他成员的认可、贡献或实验结果。保持未提交修改，避免无关重写。只有改变用户已确定的研究范围才需要重新确认任务目标；范围内的技术取舍由 AI 自行研究与完成。

## 每轮 agent 的工作顺序

1. **同步可读版本。** 运行 `git status --short --branch`、`git log -5 --oneline`，联网时 `git fetch origin`。fetch 不合并文件；工作区干净且可快进时再同步当前分支。存在本地修改或分叉时保留内容并处理合并。离线时按已知版本继续，记录基线。
2. **读取相关变化。** 阅读五人交接及引用的决定；用 `git diff <已检查提交> HEAD -- docs/` 检查增量，进一步阅读关联成果。首次工作或旧提交不可用时阅读现状。远程尚未合入的成果可按提交读取，注明来源提交。
3. **研究、决策、交付。** 在本模块完成有明确结论的设计和验证，按上节主动解决差异。已有方案足够时直接复用，缺少输入时补最小替代，不停在问题清单。
4. **提交可复用成果。** 更新模块文档、决定、验证和交接记录，遵循 [Git 规范](../AGENTS.md)。按当前任务的提交授权推送到共享仓库；本地 commit 尚未推送时，其他成员无法读取。分支协作注明已推送的分支或 PR 入口。
5. **下一轮吸收新成果。** 新提交到来后核对受影响部分、运行适用检查或重新推演，修订方案并留下新的决定。开始和提交前各检查一次远程即可，无需持续轮询。

各 agent 在被成员启动时执行上述流程。Markdown 提供协作规则，后台自动唤醒或跨成员 agent 实时通信需另行配置；当前通过共享仓库传递成果。

## 完成状态与最终整合

- **模块可交付**：当前已声明输入和假设下，方案、关键决定、引用和验证说明完整。其他人尚未提交不影响这一状态。
- **集成待检查**：模块可交付，但尚未核对实际组合中的相关成果。记录具体版本和剩余事项。
- **集成已检查**：已核对指定提交上的接口、语义和关键情境，保留证据；后续变化再做增量检查。

架构整合是对已有成果的持续汇总。ZQO 负责维护总体说明，任何正在工作的 AI 都可补齐必要的数据流或兼容说明。最终报告由现有模块组成，并核对课程覆盖和集成状态；不能把各模块分别完成视为整体已验证。
