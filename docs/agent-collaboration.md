# SkyRoute 独立推进与异步协作

五位成员及各自的 agent 都可从仓库现有资料开始。每人先形成可阅读、可复核的模块初稿，再依据其他成员提交的成果逐步对齐。总体架构与各模块同步演进。

## 开工所需资料

阅读 [课程要求全文](course-requirements.md)、[项目说明](project-brief.md)、[共同场景约定](scenario-contract.md)、[分工](team-tasks.md) 和自己的交接记录，即可开始本模块。课程 PDF 和贡献表的内容已写入 Markdown，无需访问任何成员电脑上的原件。技术论证中使用的新论文、技术资料和实验依据，由各成员补充可核查引用。

共同场景约定中的 `starter-v0` 提供初稿可共用的坐标、时间、版本和查询表达。数据库、空间离散方式、风险公式、部署方式等由各模块先提出有依据的方案；方案写明输入输出即可供其他 agent 复用。

## 每轮 agent 的工作顺序

1. **检查工作区与版本。** 执行 `git status --short --branch`、`git log -5 --oneline`，记录本轮读取的提交号。联网时执行 `git fetch origin` 查看远程更新；fetch 只更新远程引用，不会合并工作文件。工作区干净且可快进时再同步当前分支；有本地修改或分叉时先保留工作并处理合并，不能强制覆盖。暂时离线时按已知版本继续，并在交接记录中说明。
2. **读取增量。** 阅读五人的交接记录；对照自己上次记录的“已检查提交”，用 `git diff <已检查提交> HEAD -- docs/` 查看当前分支新增的变化，再阅读与本模块有关的成果文件。首次工作直接阅读现有文件。旧提交不存在时重新阅读现状并记录新的基线。尚未合并的远程成果可以按提交读取，但应记录远程提交号，不能当作本地已经集成。
3. **独立推进。** 现有成果可直接引用；上游内容缺失时写出所需输入输出，使用临时假设、合成样例或占位函数完成可独立论证的部分。明确哪些内容是设计、哪些验证已执行。
4. **检查兼容性。** 核对坐标与高度、单位、时间窗、版本、风险含义和返回状态。发现差异时先在自己模块完成转换说明或兼容调整；涉及共同语义的差异按下节记录，继续不受影响的工作。
5. **交付可复用内容。** 更新自己的成果及交接记录，包含读取的版本、可复用输出、假设、验证和跨模块影响。提交只包含本次相关文件，遵循 [提交规范](../AGENTS.md)。成果进入共享分支后，其他 agent 在下一轮读取；只存在个人电脑或未合入的分支上时，注明其提交或分支入口。

开始和提交前各检查一次已知远程变化即可，无需持续轮询或等待所有成员回复。各成员使用自己的工作副本；并发修改通过 Git 合并，保留其他人的内容。

## 假设、差异与共同约定

- **共同约定**：项目说明、课程要求及 `scenario-contract.md` 中的共同语义作为当前基线。
- **模块临时假设**：在自己的成果中写明假设、原因、适用范围及替换方式，编号可用 `LQ-A1`、`ZC-A1`。例如风险字段尚未确定时列出所需含义及模拟输入，后续映射到 LQ 的正式定义。临时假设不自动成为其他模块的决定。
- **待对齐事项**：记在提出者的交接记录，写明对应成员、文件/字段、差异、建议和受影响的局部结论。字段改名可用映射处理；高度基准或风险定义冲突等问题未解决前，相关结果保留“待对齐”状态。
- **共同约定变更**：先在自己模块提出兼容或迁移办法；受影响成员在各自记录中留下复核结果，再由对应领域负责人汇总更新共同约定。ZQO 协调跨模块流程，YHT 负责数据语义，LQ 负责风险语义，ZC 负责规划语义，LJ 负责运行与验收语义。更新时写清影响和旧样例的处理方式。

其他人的新稿是可引用的成果，是否采纳取决于证据和兼容性；不能仅凭提交时间较新就覆盖共同定义。无法解决的冲突只影响依赖该决定的结论，模块其余部分继续推进。

## 一份模块初稿应能独立阅读

每份初稿用适合本模块的篇幅说明：解决的问题、输入与假设、主要方案及取舍、对外输出、证据与验证。引用其他模块时附相对路径和已读取的提交号；实验结果包含条件，未执行的实验写为验证计划。

交接记录区分“初稿可复用”“待对齐”和“已对齐”，并列出可继续推进的下一步。个人完成初稿无需等待整体方案；整合为最终报告时，再核对课程覆盖、共同语义及尚未关闭的差异。
