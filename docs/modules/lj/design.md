# 运维保障与验收设计

## 1. 运行边界

LJ 负责模拟系统的可观察性、异常分类、恢复动作和验收判据，不代替 ZQO 的发布事务、LQ 的风险模型或 ZC 的路径搜索。运行层只消费已发布快照和 Q1/Q2 结果，并保留关联标识以便重放。

一次 Q1 结果至少记录：

| 字段 | 运行含义 |
| --- | --- |
| `query_id` | 任务和日志关联键，不能用用户可读名称代替 |
| `status/reason` | `feasible`、`infeasible` 或 `unknown` 及可操作原因 |
| `versions` | `scene`、`airspace`、`risk_data`、`risk_model`、`planner_config` 五类版本 |
| `planned_at/departure/window` | 规划时刻、出发时刻和时间窗 |
| `elapsed_ms/expanded/edge_checks` | 运行预算和搜索量证据 |
| `path/segments/metrics` | 可行路线的完整航段、距离、时间和风险分量 |

`infeasible` 只表示在结果声明的有限搜索范围内确认无解；超时、输入不完整、版本不一致和恢复校验失败必须是 `unknown` 或操作失败。

## 2. 状态、指标与告警

运行状态采用以下最小集合：

| 状态 | 进入条件 | 对外行为 | 恢复 |
| --- | --- | --- | --- |
| `healthy` | 发布快照可读，依赖检查通过，验收样例通过 | 允许正常 Q1/Q2 | 持续指标采集 |
| `degraded` | 非关键指标超阈值、单个重试中的依赖异常 | 允许明确标注受影响范围的读取 | 重试、限流或切换只读 |
| `blocked` | 快照不可读、审计不可写、关键版本不完整 | 停止发布及受影响查询 | 修复依赖后重新验收 |
| `revalidating` | 发布版本变化或旧路线命中受影响对象 | 历史结果保留，但不标为当前推荐 | 重新执行 Q1/Q2 验证 |

建议记录的指标：

- `query_total{status,reason}`、`query_latency_ms`、`unknown_total`；
- `snapshot_version_mismatch_total`、`stale_input_total`、`audit_write_failure_total`；
- `revalidation_queue_depth`、`revalidation_age_seconds`、`recovery_total{outcome}`；
- `publish_validation_failure_total` 和当前可用快照版本。

告警必须带 `query_id` 或 `operation_id`、组件版本、UTC 时间、原因和建议动作。只告警“服务异常”不足以支持恢复和审计。

## 3. 异常分类与动作

| 异常 | 判定 | 动作 |
| --- | --- | --- |
| 数据缺失或覆盖不足 | `complete=false`、关键字段缺失或风险 `q=null` 且无法绕行 | 返回 `unknown`，记录缺失组件和快照 |
| 数据过期 | 组件有效期未覆盖规划时间窗 | 不继续规划；重新读取或等待新发布 |
| 版本混用 | 查询版本与快照版本不完全相等 | 拒绝结果，固定单一快照后重试 |
| 搜索超预算 | `elapsed_ms`、扩展数或队列年龄超阈值 | 返回 `unknown`/重试，不伪装成 `infeasible` |
| 发布校验失败 | 几何、时间、来源、风险或兼容性校验失败 | 不切换可用清单，保留旧版本 |
| 审计写入失败 | 不能持久化敏感操作或发布事件 | 阻止发布、导出和恢复确认；普通查询按策略降级 |
| 恢复摘要不匹配 | 恢复对象内容摘要与版本不一致 | 停止重放，隔离对象并告警 |

## 4. 日志与审计

运行日志使用结构化事件，不记录未经授权的细粒度暴露数据。最小字段为 `event_id`、`operation_id`、可信 `actor/role`、动作、对象类型、版本、UTC 时间、结果、原因、耗时和错误类别。发布、回滚、导出、权限变更和恢复必须进入不可变审计流；日志本身不能替代业务审计。

日志保留应遵循 LQ 的治理约束：合成实验保留可重放材料至验收完成并留出复核窗口；真实数据的保留周期由许可和业务规则决定。敏感内容只保存引用、摘要和最小解释，避免把人口暴露明细复制进运行日志。

## 5. 恢复流程

1. **止损**：标记受影响快照或结果为不可推荐，停止发布切换和敏感导出。
2. **定位**：按 `operation_id` 汇总日志，确认失败阶段、版本和依赖。
3. **保留**：保留最后一个已验收快照及其审计引用，禁止静默覆盖。
4. **修复/重放**：修复输入或依赖后，以新发布版本重新校验；撤销用新清单指向已核验对象。
5. **复验**：运行正常查询、缺失数据、版本混用、更新失效和权限拒绝样例。
6. **恢复**：全部关键验收通过后才从 `blocked`/`degraded` 转回 `healthy`，并记录恢复结论。

恢复成功不等于旧路线仍然有效。任何影响建筑、空域、风险、模型或规划配置的版本变化都要让命中的旧结果进入 `revalidating`。
