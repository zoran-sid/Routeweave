# LJ 验收情境与结果

## 1. 验收矩阵

| 编号 | 情境 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| A1 | 完整快照上的可行 Q1 | `pass`，五类版本相等，指标非负 | `test_feasible_result` |
| A2 | Q1 返回有限域无解 | `pass`，保留 `infeasible` 和搜索范围 | `test_infeasible_result` |
| A3 | 缺失数据或风险未知 | `fail`（若标成成功），正确结果应为 `unknown` | `test_unknown_requires_reason` |
| A4 | 查询与当前快照版本混用 | `fail`，不得继续使用结果 | `test_version_mismatch` |
| A5 | 发布校验失败 | 旧可用版本不变，操作进入失败审计 | `test_failed_publish_keeps_previous_snapshot` |
| A6 | 空域/风险更新命中旧路线 | 旧路线转为待复验，新版本重新验证 | `test_affected_update_requires_revalidation` |
| A7 | 查询超过运行预算 | `fail` 或 `unknown`，不能改写成无解 | `test_budget_overrun` |
| A8 | 恢复对象摘要不匹配 | 恢复停止并告警 | `test_recovery_digest_mismatch` |

## 2. 已执行验证

原型使用标准库 `unittest`，不依赖数据库、网络或真实身份系统。测试覆盖：

- 成功、有限域无解和未知结果的字段完整性；
- 五类版本的全量一致性；
- 发布失败保持旧快照；
- 变化组件命中路线后的重新验收要求；
- 预算超限、审计关联和恢复摘要校验。

测试结果应以执行命令输出为准；这些是合成输入上的运行规则验证，不是生产可用性、真实数据库延迟或安全概率测量。

## 3. 验收阈值与未覆盖项

当前模块只把“结果不能被误报”和“失败可恢复”作为硬验收项。具体延迟阈值、吞吐量、告警路由和保留周期需要部署环境及课程团队确认后设置，不能用本地合成运行时间替代。

仍待接入的项目：

- ZQO 的原子发布清单、事务隔离和真实更新通知；
- LQ 的实际审计存储、权限策略和敏感字段脱敏；
- YHT 的空间数据质量、覆盖率和索引健康指标；
- 真实服务的身份认证、日志管道、备份恢复演练和故障注入。
