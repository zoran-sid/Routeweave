# LJ 跨模块集成说明

## 已检查输入

本模块读取仓库 `de2033a` 及其工作区中的共同约定、ZC 与 LQ 已交付成果、ZQO/LJ 交接记录。当前没有可接入的 ZQO 发布服务或 YHT 数据模型，因此运行原型使用 ZC 的 `scenario.json` 字段和明确的合成状态。

## 字段映射与判据

| 来源 | 复用字段 | LJ 检查 |
| --- | --- | --- |
| ZC Q1 | `query_id`、`status/reason`、`versions`、`path/segments`、`metrics`、`elapsed_ms` | 状态与指标互相一致；失败不填零指标；版本与当前快照完全相等 |
| ZC Q2 | 航段状态、原因、风险和来源 | `forbidden/unknown` 不得被展示为可执行；更新后重新检查整条旧路线 |
| LQ | `unknown` 优先级、风险来源、审计与最小权限 | 风险未知不得默认零；敏感读取、发布和导出需要审计 |
| ZQO | 不可变五类版本、发布/撤销/回滚 | 只接受已切换清单；发布失败不产生“新版本成功”标签 |
| YHT | 坐标、质量、来源和覆盖范围 | 单位/基准或覆盖不明时阻止发布并标记未知 |

## 当前兼容性结论

1. ZC 的 `unknown`、版本绑定、更新后旧路线复核规则可直接作为运行验收输入。
2. LQ 的审计失败阻止发布和敏感导出规则与本模块的 `blocked` 状态一致。
3. ZQO 接入时必须提供当前清单版本、发布操作 ID、原子切换结果和旧版本保留引用；仅提供内容摘要不足以证明事务发布。
4. YHT 接入时必须补齐覆盖率、质量状态和坐标转换记录；缺失时不能沿用 ZC 的合成完整标记。

## 接入后复验

替换合成输入后，至少重跑 A1–A8；另外增加发布读写交错、审计存储故障、备份恢复摘要错误和跨组织读取拒绝四类情境。验收结果应记录实际提交号、部署版本、操作 ID 和未覆盖项。
