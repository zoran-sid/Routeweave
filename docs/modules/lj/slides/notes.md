# LJ 第9–10页展示文字与讲稿

## 第9页：运行保障

**标题：从查询结果到可运行服务**

- Q1/Q2 结果固定绑定 `scene`、`airspace`、`risk_data`、`risk_model`、`planner_config` 五类版本。
- `healthy / degraded / blocked / revalidating` 四种状态对应可观察、降级、停止和重验动作。
- 重点指标：查询延迟、`unknown` 比例、版本不一致、审计失败、重验队列和恢复结果。
- 所有告警带操作 ID、版本、原因和建议动作；日志只保留最小必要信息。

**讲稿：** 我们不把“服务有响应”当作“结果可信”。缺失、过期、版本混用和超预算都要显式进入未知或阻断状态；发布更新后，旧路线先保留历史标签，再通过完整航段检查重新验收。

## 第10页：异常恢复与验收

**标题：失败可见、恢复可重放**

| 情境 | 处理 |
| --- | --- |
| 发布校验失败 | 不切换可用清单，旧版本继续可追溯 |
| 审计写入失败 | 停止发布、导出和恢复确认 |
| 版本变化命中旧路线 | 标记待复验，按新版本重规划 |
| 恢复摘要不匹配 | 隔离对象并告警，不进行重放 |

- 验收覆盖正常、无解、未知、混版、更新、预算和恢复八类情境。
- 原型为标准库合成验证；真实数据库、身份、监控和灾备接入后再做部署级演练。

**讲稿：** 恢复不是静默回滚。我们保留最后一个已验收快照，通过新版本重新校验，并把每一步关联到审计事件。这样既能恢复服务，也能说明哪一个版本产生了哪一条推荐路线。
