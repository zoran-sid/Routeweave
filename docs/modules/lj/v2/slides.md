# LJ v2 展示文字（建议第9–10页）

## 第9页：备份恢复与一致性核验

- 单机原型：SQLite WAL；生产目标为 PostgreSQL/PostGIS 主库与只读副本。
- `Connection.backup()` 复制数据库；恢复后依次检查 `integrity_check`、外键、发布父链、`content_hash` 和历史查询摘要。
- `route_graph_cache` 是可重建派生数据，不与数据库事实源混备份。
- 合成实测：R0/R1 两个发布；正常恢复全部通过；截断备份被检测并隔离。
- 失败动作：阻止推荐、保留最后已验收发布、返回 `unknown`，不静默切换。

## 第10页：权衡、局限与结论

- 五项取舍：模式质量、不可变发布、隐私治理、派生图新鲜度、恢复目标与成本。
- LJ 取舍：更短 RPO/RTO 需要更频繁备份、热副本和演练；低成本单机原型不等于生产高可用。
- 规模估算：2,400 栋、三年约 2 GB 热数据；云对象存储费用为公开单价下的模拟估算。
- 结论：恢复验收必须同时证明文件完整、版本可追溯、历史可重放、缓存可重建。
- 后续：目标规模故障注入、跨区切换、真实价格与告警阈值验证。
