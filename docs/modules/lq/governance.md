# 数据安全、隐私与治理方案

## 角色与最小权限

依据NIST SP 800-53 Rev.5中的职责分离、最小权限及审计保护控制[3]，本模块采用以下课程模拟设计。角色名表示业务职责，五名组员不必一一绑定这些系统角色。

| 角色 | 允许 | 禁止 |
| --- | --- | --- |
| dispatcher 调度员 | 提交本组织Q1、读取自己的路线及必要Q2解释 | 修改风险模型、导出细粒度暴露层、查看其他组织任务 |
| data_steward 数据维护员 | 写入有来源的草稿、修正质量标记 | 自行发布草稿、覆盖历史版本 |
| safety_reviewer 安全评审员 | 审核独立作者草稿、批准参数和发布 | 审批自己创建的草稿、绕过缺失检查 |
| planner_service 规划服务 | 读取已发布的最小风险切片、写入评估记录 | 读取个人轨迹、修改源数据或权限 |
| auditor 审计员 | 只读审计记录及受控的重放材料 | 删除或修改事件、改变推荐 |
| operator 运维人员 | 查看健康指标、执行受审计恢复 | 默认读取敏感暴露明细、审批模型 |

角色校验在API层统一执行，身份从认证会话获得，不能信任请求体自报角色。Q1/Q2和导出均需鉴权，按组织限制任务访问，服务间使用单独凭据。数据库可用GRANT与行级策略提供第二层限制。PostgreSQL 18的RLS启用后无策略时默认拒绝，但超级用户、BYPASSRLS角色及通常的表拥有者会绕过它[4]。所以应用角色不得拥有表，不授予BYPASSRLS或超级权限，按需FORCE RLS，并以实际连接角色验证读取和写入策略。RLS不能替代字段脱敏及导出控制。

## 发布、回滚和审计

1. 数据维护员接入草稿，校验坐标、时间覆盖、来源、许可和数值，计算内容摘要。
2. 安全评审员检查模型假设、硬阈值、包络与缺失策略，必须与草稿作者不同。拒绝记录原因。
3. 发布服务写入不可变的风险数据和模型对象，通过全部检查后将它们绑定到可用发布清单，原子切换清单由ZQO负责实现。草稿或部分写入不能进入查询。
4. 查询固定五类版本；返回当前推荐前检测清单变化。新版本触发受影响旧路线复核和重规划，原结果保留历史标签。回滚是发布新的可用清单指向已核验对象，不能静默改写旧版本内容。
5. 记录actor、可信角色、UTC事件时间、动作、对象版本、变更前后摘要、原因、结果和关联ID。审计对象包括读取敏感层、导出、角色改变、模型/阈值改变、发布、拒绝、回滚和重放。

建议以事务发件箱绑定业务变更与审计事件，再复制到只有审计服务可追加的独立存储。缺少持久审计写入时，敏感发布和导出停止；普通查询的可用性策略由LJ区分。哈希链只能帮助发现篡改，不能阻止有权重写整条链的人，因此保留独立校验点与备份。传输使用TLS，密钥独立于仓库，静态数据与备份加密，恢复后核对摘要和引用完整性。上述为设计，当前代码只执行职责分离策略模拟。

## 隐私、伦理与滥用

本模块只保存合成区域级数据，不收集个体位置、住宅身份或设备标识。真实接入优先使用授权的聚合人口信息，记录来源许可、用途、保留周期与地理适用范围。对外Q2提供来源类别、质量和区域解释，限制导出原始高分辨率时序切片。聚合仍可能泄露小群体活动模式，因此不能仅凭去标识化就认定匿名。

课程模拟的保留策略：可重放的发布对象、模型和关联审计保留至课程验收完成并留出30日复核窗口；中间草稿和无引用缓存7日清理；这些是内部参数，真实保留要求需依据数据许可和实际用途再制定。删除应检查查询引用、审计义务和备份生命周期，保留聚合重放快照时避免附带个人数据。

热点建模可能让路线长期绕过某商业区，却把飞行负担转给住宅区。评估应同时输出各区域经过次数、暴露代理累计量、白天/夜间差异及数据误差敏感性；不能通过稀释人口统计或降低某区域质量标准获得更优分数。禁止将暴露层用于识别个人、监视敏感场所或将未知区域伪装成低风险。导出使用用途约束、限频和审计，隐私保护造成输入不确定时让状态进入未知或采用经过评审的保守参数。

## 可执行验收清单

| 场景 | 验收判据 | 当前证据 |
| --- | --- | --- |
| 作者自审发布 | 拒绝，留关联ID与原因 | `can_publish`策略测试已运行，实际日志落库待实现 |
| 调度员发布模型 | 拒绝 | 策略模拟已运行 |
| 独立评审发布 | 前置校验全部通过后允许 | 仅角色/作者判定已运行 |
| 跨组织读取、伪造角色、敏感字段导出 | 拒绝或按字段最小化，并记日志 | 设计检查项，未声称API/数据库已部署 |
| 发布写入或审计写入失败 | 不切换清单，历史结果仍引用旧版本 | ZQO/LJ集成验收项 |
| 审计修改、重放缺版本、恢复摘要错配 | 告警并停止受影响发布/重放 | 运维验收设计，未实测 |

这些检查可由LJ复用，数据库及身份服务接入后应从实际应用角色执行，而非只检查配置文本。
