# LQ 第5–6页展示与讲稿

## 第5页：地面风险与航线取舍

建议讲稿（约60–75秒，正式总时长由教师通知）：

我们的风险评估关注无人机失效后对地面人员的影响。需要同时考虑影响范围、暴露和后果，因此人口密度本身不足以判断安全。为了在课程中验证设计，我们使用q等于暴露E乘以后果C的合成代理。对完整航段的地面投影扩展5米，取任务窗内相交区域的最大q。q达到0.9就禁止，数据缺失则标记未知，只有允许的航段才能比较距离与风险。相同建筑场景中，lambda从0增加到2后，航程由116.57米增加至133.14米，累计代理下降约86.7%。这解释了绕行的代价，数值属于合成模拟。公式、参数、来源和五类版本一起保存，确保结果可复核。

来源：EASA SORA概念、Oh与Yoon 2022时变人口研究、`results/evaluation.json`，具体链接见参考文献[1][2]。公式和0.9阈值为本项目合成假设。

## 第6页：风险数据的发布与追溯

建议讲稿（约60–75秒）：

数据库需要保证一条航线使用的风险数据可解释、可追溯。维护员先提交带来源的草稿，独立安全评审员核对参数与质量，然后发布服务将数据和模型绑定到不可变版本。查询固定场景、空域、风险数据、模型与规划配置五类版本，风险更新后重新验证推荐航线。调度员只能读取必要解释，规划服务只读取已发布切片，审计员独立查看记录。我们还限制细粒度暴露导出，记录拒绝和角色变更，防止以数据缺失换取更低风险评分。当前19项风险测试与21项规划测试通过，部署层面的数据库权限和日志防篡改需要在真实服务接入时继续验收。

来源：NIST SP800-53 Rev.5，PostgreSQL18 RLS官方文档，项目治理设计。参考文献[3][4]。

## 可能的提问

- **为什么不用真实事故概率？** 尚无机型失效率、落点分布和伤害校准数据；当前代理用于规则与取舍验证，未来需要经过校准的物理模型。
- **0.9是谁规定的？** 合成阈值，便于展示硬约束。实际阈值须结合机型、场景和安全评审，不能直接用于实际飞行。
- **提高lambda能不能越过禁飞或高风险区？** 不能，硬约束在搜索前排除候选边。
- **升高为何仍有地面风险？** 当前影响包络在地面上计算，假设高度不会消除暴露；真实落点模型可能随高度扩大影响范围。
- **未知和禁止有什么区别？** 禁止已有足够证据拒绝；未知表示证据不足。两者均不能作为允许边，但未知不能用于证明整个空间无解。
- **为什么属于数据库课程？** 重点包括时空覆盖、版本绑定、来源血缘、质量校验、权限和发布审计；风险数值是驱动这些数据管理要求的具体业务。
