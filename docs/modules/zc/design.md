# 三维航线查询与数据管理设计

## 1. 查询问题与选择

物流调度员需要根据给定起终点、出发时间和任务窗口查询可行路线，并知道路线采用了哪些环境、空域与风险数据。本模块将 Q1 分为输入校验、约束过滤、图搜索及结果追溯。Q2 的航段检查提供约束原因和来源，用于解释查询和重新校验旧航线。

采用10米间距的三维网格，节点表示无人机中心的局部坐标，每个节点最多连接26个邻居。候选边是两个节点之间的完整直线段，允许水平、垂直和空间对角移动。建筑和禁飞几何以封闭实体处理，安全缓冲后与航段相交的边不能进入搜索。所有比较使用同一网格、相同约束和代价。[1][2]

| 候选 | 适用性与代价 | 本模块选择 |
| --- | --- | --- |
| 规则三维网格 | 邻接稳定，易复核和对照；细网格增加节点与几何检查 | 采用，先用10米网格完成证据链 |
| 三维可见图／自由航点图 | 可减少方向离散偏差；复杂实体的候选连接与精确碰撞更难维护 | 保留为后续精度对照 |
| 自适应八叉树 | 大片空域可减少状态数；跨层邻接和更新映射增加实现成本 | 大场景中另行评估 |
| Dijkstra | 非负边权上的基准搜索；无需启发式 | 作为可复核对照 |
| 3D A* | 用目标方向下界聚焦搜索，仍保留声明图上的最优代价 | Q1 当前方案 |
| D* Lite | 在相似查询之间复用搜索状态；需可靠的变化边集合 | 设计候选，尚未实现或计时 |

这里的“3D”来自状态、邻接和碰撞几何。搜索逻辑沿用 A*；Dijkstra 可写为相同搜索中的 `h=0`。独立解析例、几何边界测试与启发式一致性检查共同补充两种搜索共用约束内核带来的验证局限。

## 2. 可复现的场景和时间含义

所有输入采用 [starter-v0](../../scenario-contract.md)。场景为 `zc-synthetic-v1`，来源统一标记 `synthetic-zc-v1`。网格模型中的数值为精确定义的合成参数，未估计真实测绘误差。

| 项目 | 合成设定 |
| --- | --- |
| 坐标及高度 | `starter-v0-local-m`，x向东、y向北、z向上，单位米；平坦地面z=0 |
| 中心搜索域 | x/y ∈ [0,100]，z ∈ [10,70]；847个未过滤节点，最多22,022条有向候选边 |
| 起终点 | S=(0,50,20)，G=(100,50,20)，均为已在空中的任务点 |
| 建筑 B-1 | 实体盒 [40,60]×[20,80]×[0,35] |
| 运动与缓冲 | 速度10 m/s；实体各轴扩展2米，采用保守立方体包络；不建模转弯半径、风与动力学 |
| 查询时间 | 规划与出发：2026-11-04T00:00:00Z；任务窗 [00:00,00:10) UTC |
| 数据覆盖 | 场景、空域、风险数据声明覆盖 [00:00,01:00) UTC，完整性标识为真 |
| 基础风险 | 全搜索域都有背景 q=0.05；热点水平范围 [30,70]×[35,65]，q=0.70 |

场景时钟固定为模拟任务时间，运行实验的实际日期另存于结果元数据。数据有效区间表示模型输入在模拟任务中的覆盖，不把实际运行日期冒充空域发布时间。

### 完整航段的空间检查

以参数式 `p(t)=a+t(b−a), 0≤t≤1` 表示航段。对每个轴计算航段进入和离开扩展盒的参数范围，求三个范围与 `[0,1]` 的交集。交集非空即阻挡，包含接触表面、端点落入实体、航段完全位于实体内部及对角穿角。平行于盒面的轴单独检查该坐标是否在范围内。

轴向扩展2米包含半径2米的球形缓冲，会在角部更保守。搜索域本身限定无人机中心，不能由此推断真实运行空域的边界许可。水平地形由最低中心高度10米和2米包络保持净空；真实地形须转换成可检查的实体或高度场后接入。

### 时间窗检查

对已发布限制 `[a,b)` 和查询窗口 `[d,e)`，仅当 `a<e 且 d<b` 才纳入约束。撤销记录不再阻挡。当前采用**整窗保守策略**：只要限制在窗口内任何时刻有效，就在整次搜索中禁止相应航段。因此无需把到达时间加入节点，图在单次查询中保持静态，但可能排除实际可提前通过或等待后通过的路线。

三维禁飞盒检查使用完整包络。限高记录应用于水平区域：先求航段在扩展水平区域内的区间，再检查该区间中的最大中心高度加2米是否超过限高；等于上限允许。结果要求预计到达时刻严格早于规划窗结束。单标签加权搜索未解决额外的最迟到达资源约束；选出的最优代价路线超窗时返回 `unknown`，后续可采用时间扩展图或多标签搜索判断其他路线。

## 3. 模拟风险、硬约束与目标函数

为独立验证规划，本模块定义可替换的地面风险代理。假设相同机型和任务的单位航程失效倾向相同，失效影响落在航段地面投影周围5米的方形包络内，暴露在任务窗内保持不变。用区域归一化暴露 `E∈[0,1]` 与条件后果系数 `C∈[0,1]` 的乘积定义 `q=E×C`；样例背景取 `(0.1,0.5)`，商业热点取 `(0.875,0.8)`。二者是合成参数，风险输入直接保存其乘积。

航段风险取与影响包络相交的已知区域中最大 `q`，并覆盖整个航段长度，形成保守的分段代理。高度不会降低这个模拟 q，飞越建筑仍需计入地面暴露。未知区域返回未知，不能按零处理；未知区域能绕开时，可在全部已知允许边上返回可行路线。

硬约束先过滤建筑、有效禁飞、限高和 `q≥0.9` 的航段。阈值0.9是演示参数。可接受风险再进入目标，任何距离或风险收益都不能抵消硬约束。边和整条路线的指标为：

```text
ℓ(e) = 三维欧氏长度，单位米
t(e) = ℓ(e) / 10，单位秒
r(e) = [ℓ(e) / L0] × q_max(e)，L0 = 100米
c(e) = ℓ(e) / L0 + λ × r(e)，λ ≥ 0
J(P) = Σ c(e)，R(P) = Σ r(e)
```

`r`、`R` 和 `J` 无量纲。`R` 是按航程累计的后果加权暴露代理，可能超过1，不是失效概率或伤亡概率。固定机型的失效倾向被吸收到模拟权重，未做概率校准。时间与距离在恒速下线性相关，当前报告时间但不重复加权；能耗需要额外模型后再加入。各指标使用固定尺度而非每次候选集的最小最大归一化，保证版本相同的任务间可解释。

## 4. 启发式、正确性与伪代码

令 `h(n)=||n−G||₂/L0`。由于 `λ≥0`、`q≥0`，每条允许边满足 `c(n,v)≥||n−v||₂/L0`。三角不等式给出 `h(n)≤c(n,v)+h(v)`，且 `h(G)=0`，所以该启发式一致并且不高估剩余目标代价。有限图上的 A* 与 Dijkstra 可得到相同最优目标代价，路线本身可能因等代价排序不同而不同。[1][2]

实现按 `(f,g,坐标)` 排序，跳过已过时的队列项，并允许更小代价更新父指针；目标节点出队后回溯。每条返回航段再次调用约束检查。在无风险热点的建筑场景，可复核路线包含4条长度 `10√2` 的边及6条10米边，合计 `60+40√2=116.5685` 米。

```text
Q1(snapshot, query, algorithm):
    固定输入副本，校验五类版本、完整性、时间覆盖、坐标与参数
    缺失或不匹配 -> unknown；已知阻挡的起终点 -> infeasible
    g[start] = 0；其他 = ∞；h = 欧氏下界（Dijkstra 使用0）
    队列加入(start, g+h)
    while 队列非空:
        弹出最小(f,g,坐标)，跳过过时项
        超过搜索预算 -> unknown
        若为goal：回溯并复核，超窗 -> unknown，否则 feasible
        for 26邻居内的每个合法域节点 v:
            检查完整航段的障碍、整窗空域和风险
            forbidden：跳过；unknown：记录并跳过
            allowed：若 g[u]+c(u,v)<g[v]，更新g、父指针与队列
    若遇到未知边 -> unknown；否则 -> infeasible（限定本搜索图）
```

网格邻接度有界，堆搜索的图操作量为 `O(V log V)`，状态与队列上界为 `O(V)`；原型每条边线性扫描 B 个障碍、A 条限制及 R 个风险区，约束计算另计 `O(E(B+A+R))`。10米网格的无解只证明该离散表示及整窗策略下无解，不能外推为连续空间或允许等待的任务无解。已知允许子图上的最优也不排除未知区域中存在更优路线。

## 5. 图数据管理与规划访问

课程要求深入讨论数据管理技术。本模块选择**版本化图投影**：源数据保留对象几何、有效时间和来源，规划按固定发布清单把它们投影成带约束及代价的邻接图。图中的节点／边是可重建的派生数据，返回路线保留源版本血缘。这使图搜索与数据库事实来源衔接，并能定位哪些更新改变了边。[4][5][6]

| 数据访问方案 | 查询与更新成本 | 选择 |
| --- | --- | --- |
| 每扩展一条边就远程查询空间库 | 无需预加载；大量细粒度往返，难以跨多次读取固定版本 | 不用于当前小场景 |
| 批量读取固定版本，内存生成邻接与代价 | 几何检查在本地，缓存可绑定版本；需要加载完整规划范围 | 当前方案，原型以JSON替代数据库 |
| 持久化全部带权图边，使用图数据库 | 邻接访问直接；风险模型、时间窗或分辨率变化会产生大量派生边重建 | 大量重复查询时作为候选，需测量总成本 |

Neo4j GDS 官方文档描述把节点、关系及属性投影到内存图的机制；本模块借鉴“源数据／计算图分离”，没有宣称部署了 Neo4j 或由其内建算法完成本原型。[4] 在本场景847个节点规模下，按需邻接避免预先持久化所有边。图投影的优势来自数据布局和复用条件，不能只用搜索节点数推断数据库吞吐量。

建议的接入顺序为：读取可用发布清单，固定五类版本和窗口；批量获取规划域内障碍与风险覆盖，以及时间窗重叠的限制；校验记录完整性；在内存完成精确检查和搜索；存储查询、路径、各目标分量与依赖版本。原型不缩小搜索域，避免因局部裁剪把存在于域外的绕行路线误判为无解。后续裁剪必须注明搜索范围与扩张策略。

PostGIS 的三维相交及距离函数可辅助候选过滤，但坐标带Z并不自动解决实体内部、缓冲和垂直基准问题。数据库替换当前盒体内核时，应复用内部航段、切触、跨屋顶和穿角测试；仅检查实体表面或端点不能覆盖这些情况。[5][6]

若采用 PostgreSQL，多次读取可在一个只读 Repeatable Read 事务中保持相同数据库快照；五类业务版本仍须由发布清单明确绑定，事务隔离不能自动证明风险模型与数据语义兼容。[7] 跨数据库时采用不可变版本对象及原子发布清单，由 ZQO 的实际方案接入。当前程序使用深拷贝和显式版本匹配模拟单查询一致性。

## 6. 动态更新及 D* Lite 的适用条件

当前更新流程：收到新发布版本，确定受影响路线；在新版本和原任务窗上重新校验完整航段；标记旧推荐过时；运行新的 A*；以新版本输出可行路线或明确的失败状态。原路线仍可行也不等于仍最优：风险下降、障碍撤销或其他区域代价下降可能产生更好的替代路线，因此要求最优推荐时仍需重新搜索。[3]

D* Lite 从目标方向维护 `g`、一步前瞻 `rhs` 和不一致节点队列，在边代价变化后修复相关状态。项目适用条件是节点标识、离散精度和目标保持稳定，能够完整枚举变化边，且启发式继续满足一致性。新增禁飞可把边代价置为∞，撤销或风险下降恢复有限代价；两种方向的变化都必须处理。比较前先纳入变化定位、修复与最终路径校验的总时间。[3]

以下变化采用全量重建更容易验证：改变网格或坐标基准，换目标，风险聚合变成路径相关或出现负权，任务时间策略由整窗改为到达时刻检查，以及无法证明变化边集合完整。相同拓扑但全域风险模型变化也可能失去增量收益。当前选择全量 A* 的依据是场景小、实现已验证、更新链路短；D* Lite 的性能收益保留为待运行实验。
