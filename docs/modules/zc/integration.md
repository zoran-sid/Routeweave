## 可直接复用的输入输出

完整可运行输入为 [scenario.json](prototype/scenario.json)，多情境Q1实例为 [query-examples.json](results/query-examples.json)。`scenarios.bind` 对每个组件内容（排除version字段）计算SHA-256前12位，生成 `mock-zc-*` 版本标识，方便识别模拟参数变化；这只是实验身份标签，不作为安全签名。

| 输入 | 语义／责任 | 原型字段 |
| --- | --- | --- |
| 场景 | YHT：局部米制坐标、共同垂直基准、实体、地面和数据质量 | `scene.crs/terrain_z/bounds/obstacles/valid/complete/source` |
| 空域 | ZQO：不可变发布列表、状态、有效期及来源 | `airspace.restrictions[].id/kind/box/valid/state/source`；限高增加`ceiling_m` |
| 风险输入 | LQ/YHT：全域背景覆盖、区域暴露与后果代理、未知区域 | `risk_data.background_q/zones[].q/valid/complete/source`；q=null表示未知 |
| 风险模型 | LQ：影响包络、阈值、聚合与模型身份 | `risk_model.footprint_m/hard_threshold/aggregation/version` |
| 规划配置 | ZC：网格、包络、速度、目标权重与尺度 | `planner_config.step_m/buffer_m/speed_mps/lambda_risk/length_scale_m/version` |
| 发布／查询绑定 | ZQO/ZC：统一五类版本，避免混读 | `snapshot.versions`、各组件`version`与`query.versions`必须一致 |
| 任务 | Q1：位置、计划时刻、出发时间与任务窗 | `query.id/start/goal/planned_at/departure/window` |

空域记录的`valid`表示事件有效期，组件`valid`表示此次输入覆盖的时间；两者分开。原型不包含接收时间、发布提交时间或权限操作，接入时应保留这些字段用于Q2来源解释与更新延迟测量。

`plan(snapshot, query, algorithm='astar')` 返回：

- `status/reason`：`feasible`、`infeasible`或`unknown`，并给出原因。网格外或非网格端点当前返回unknown，不做隐式吸附；新增吸附适配时必须检查连接航段。
- `path/segments`：每个三维航点与完整有向航段，航段包含允许状态、长度、时间、代理风险、q最大值和区域来源。
- `metrics`：整条路线的米、秒、风险代理和目标代价。非feasible时为null，防止把失败显示成零风险。
- `versions`：五类不可变输入标识；`window/time_policy/search_scope`记录整窗策略及有限26邻居网格。
- `planned_at/departure/arrival`：任务时间，使用带时区时间串；`elapsed_ms`是程序墙钟耗时，二者分开。
- `expanded/edge_checks`：队列有效出队次数（含目标）及搜索中的航段检查次数，不含起终点与最终路径复核次数。

`assess_segment(snapshot, query, a, b)` 是用于Q2及旧航线复核的航段检查辅助函数，返回`allowed/forbidden/unknown`、原因、版本和窗内风险信息。区域查询、完整发布审计与外部HTTP服务由后续组合实现。

## 数据库与缓存接入规则

建议的计算图键为 `(五类版本, 网格域, 出发时间, 窗口, 整窗策略)`；路线缓存还需加入起终点、任务约束及目标配置。原型没有跨查询缓存，不能沿用未带版本的边权。

更新定位需同时考虑旧／新几何及安全包络。禁飞和建筑变化映射到三维航段包络；风险变化映射到航段的地面影响包络，不能只用航段自身的三维高度范围相交。撤销事件和代价下降也会影响最优性。无法证明定位完整时重建全图或全量重新搜索。

有限域无解的结论不能用于更大空间。若YHT只返回查询走廊，适配层需确认完整性；查询走廊被截断或缺少风险覆盖时返回unknown，或扩展加载范围后重试。源数据版本相同却内容改变违反此接口的不可变性前提，需要重新发布版本。

## 发布与查询交错走查（设计）

1. 查询Q读取清单v1并固定组件版本，开始搜索。
2. 发布者写入v2组件并完成校验，最后切换可用清单；写入失败时不发布v2。
3. Q继续用v1完成，结果仍标记v1；展示“当前推荐”前比较当前可用清单，若已变为v2则将Q标为待重验。
4. 对v2重新校验和规划，成功结果绑定v2；历史v1保持可重放。删除v1数据前需满足引用保留策略。

该交错是设计走查。本次已运行的证据是版本不符拒绝、输入不被修改、更新后旧路线失效与新路线生成；实际事务隔离、乱序通知和发布失败测试留待ZQO/LJ实现接入。
