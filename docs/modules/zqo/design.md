# 动态空域发布与版本一致性

## 1 业务问题与方案

SkyRoute 的调度员查询配送航线时，空域管理员可能正在发布临时禁飞区域。如果查询先读取旧禁飞列表，再读取新风险数据，所得路线就难以重放和解释。本模块把一次可用输入组织为不可变的发布包，并以一条当前版本指针决定新查询读取哪一包。查询固定版本后运行规划，返回时再核对当前发布状态。

本方案承接 YHT 的三维数据定义、LQ 的风险规则和 ZC 的规划接口。基础场景采用 ZC 的合成城市与10米网格，风险输入通过 LQ 的时段适配器生成。两项核心服务继续使用 Q1（三维航线查询）和 Q2（航段或区域状态与来源查询）。本模块提供可运行的发布目录及航段级 Q2 组合，完整区域服务作为总体架构中的服务接口保留。

## 2 空域生命周期与时间含义

空域限制先进入草稿，经质量检查和独立复核后写入新的发布包。修改和撤销都生成新版本，历史内容保持不变。限制是否影响某次任务，由它的有效区间和任务时间窗决定。

| 环节 | 数据处理 | 查询表现 |
| --- | --- | --- |
| 接入草稿 | 保留限制编号、三维范围、来源及接收时间 | 草稿不进入可用发布目录 |
| 校验与复核 | 核对几何、时间覆盖、来源和五类输入兼容；审核人与作者不同 | 校验失败返回原因，当前版本保持不变 |
| 发布或修改 | 写入不可变对象，提交完整发布清单 | 提交之后的新查询读取新版本 |
| 撤销 | 新版本把对应限制标为 `revoked`（已撤销） | 重新优化路线，历史版本仍显示原限制 |
| 到期 | 按有效区间计算，不改写原记录 | 到期限制不阻挡新任务，历史任务按原时间重放 |
| 恢复发布 | 重新核验候选对象，创建新的发布编号 | 保留恢复前后的审计关系 |

时间区间沿用 `[start, end)`（含起点、不含终点）。例如限制在00:05生效、00:08失效，而任务窗为00:00至00:10，ZC的整窗保守策略会避开该限制。限制恰好在任务窗开始时失效则不参与本次判断。

| 字段 | 中文含义 | 用途 |
| --- | --- | --- |
| `valid` | 事件有效区间或数据覆盖区间 | 判断任务窗内的限制及输入完整性，两种区间分别保存 |
| `received_at` | 平台接收时间 | 衡量来源传播和接入延迟 |
| `published_at` | 平台发布记录时间 | 追溯处理过程，原型在提交前记录，不能直接当作精确提交时刻 |
| `planned_at`、`departure`、`window` | 规划时刻、出发时间和任务窗 | 沿用 ZC 查询语义 |
| `checked_at` | 返回前核对当前发布状态的时间 | 标明结果新鲜度的判断时点 |

固定版本解决“读了哪份数据”，有效区间解决“该限制何时适用”。验证样例的任务时钟固定在2026年11月4日UTC，程序运行与落库时间单独记录，因此样例属于历史模拟任务重放。

## 3 发布目录与技术选择

| 候选 | 优点 | 主要代价与结论 |
| --- | --- | --- |
| 直接覆盖各表的当前数据 | 写入流程短 | 多次读取可能混用版本，历史重放依赖额外日志，未采用 |
| 单库只读可重复读事务 | 多条查询保持数据库快照 | 长事务增加资源保留，业务模型兼容仍要另外检查，适合批量装载阶段 |
| 不可变对象与原子发布清单 | 历史可追溯，计算可脱离数据库长事务 | 增加保留空间和发布检查，作为主方案 |
| 跨服务分布式提交 | 可协调多个可变存储 | 恢复与运维复杂度较高，本组规模优先集中发布目录 |

部署设计采用关系型事务目录管理发布清单、当前指针和审计发件箱。PostgreSQL 18 可作为目录候选：发布者锁定当前指针行，核对基线后提交；读端批量加载可采用只读可重复读事务。[1][2] 场景几何的具体存储与索引仍由 YHT 完善，本模块只要求它能按不可变版本取得完整输入。

发布清单绑定 `scene`（场景）、`airspace`（空域）、`risk_data`（风险数据）、`risk_model`（风险模型）、`planner_config`（规划配置）五类版本。另设 `release_id`（发布编号），代表一次经过检查的组合。两个发布可以复用同一组件，但组件编号相同就必须代表相同内容。

| 目录实体 | 关键内容 | 一致性规则 |
| --- | --- | --- |
| `components`（组件对象） | 类型、版本、完整内容 | 类型与版本组成唯一键，禁止同号改内容 |
| `releases`（发布记录） | 发布编号、五类版本、内容摘要、上次发布、来源时间和审核者 | 提交后不可改写，原型同时保存完整JSON发布包 |
| `head`（当前指针） | 当前可用发布编号 | 只在发布事务中切换 |
| `audit`（发布审计） | 发布编号、操作者、动作 | 成功发布与审计同一事务写入 |
| `outbox`（待发送事件） | 发布编号、投递状态 | 与业务更新同一事务提交，供后续通知处理 |

摘要帮助检查内容是否变化，身份认证和数据库权限仍由部署层承担。原型中的审核角色是可信测试参数，沿用 LQ 的作者与评审员分离规则。

## 4 发布事务与查询流程

一次发布先验证候选输入及审核条件，再执行以下短事务。`expected`（预期基线）要求发布者基于当前版本工作，避免两个发布者相互覆盖。`request_id`（请求编号）用于网络重试：相同请求返回原发布编号，内容改变则拒绝复用编号。

```text
开始发布事务并取得当前指针的写入权
若请求编号已成功提交：核对请求摘要，返回原发布编号
比较当前发布与 expected，基线过期则拒绝并要求重新校验
写入或复用五类不可变组件
写入发布记录、成功审计和待发送事件
切换当前指针
提交事务
任一步失败：回滚本次全部写入
```

待发送事件与业务变更同库提交，解决“目录更新成功但通知没有留下”的双写问题。[3] 消费者将通知作为更新提示，重新读取权威目录，按发布编号去重和避免倒退。原型验证待发送事件落库及重复、乱序、遗漏提示下的目录核对；消息中间件与实际投递重试属于部署环节。

Q1先固定一份发布包并检查覆盖范围，随后在内存中运行ZC的A*。搜索结束后，服务通过新的目录读取核对当前发布。若已经更新，原结果保留其历史版本并标记 `stale`（已过时），重新校验和规划后才生成新推荐。`current_at_check` 表示在该次核对时仍为当前版本，界面应显示核对时间，并在再次采用路线前重新核对。

ZQO补充了风险时间窗的接入约束。LQ的 `compile_profiles`（时段风险编译函数）会对任务窗内取最大值，因此派生风险数据必须携带 `compiled_window`（编译时间窗）。本模块的 `prepare_risk`（风险准备函数）写入该窗口并重新绑定版本，遇到不同窗口时返回 `unknown`（未知）。后续多窗口服务应从固定发布中的原始暴露时段重新编译，保留父发布与派生版本，不能复用其他窗口的聚合结果。

## 5 更新、恢复与运行取舍

当前场景较小，任一相关发布发生变化后，先复核旧路线，再全量运行A*。撤销禁飞或风险下降也会产生更优路线，因此更新检测覆盖成本上升和下降。图投影、路线缓存必须包含五类版本、时间窗及目标配置；原型不启用跨查询缓存。

| 取舍 | 本模块选择 | 影响 |
| --- | --- | --- |
| 新鲜度与读取稳定性 | 查询固定完整发布，返回前重新核对 | 更新频繁时需重算；短暂过时状态可被明确识别 |
| 发布并发与可解释性 | 发布按当前指针串行提交，过期基线拒绝 | 减少覆盖冲突，发布高峰可能等待或重试 |
| 历史重放与存储 | 原型保留全部已发布对象 | 占用空间随版本增长，后续按引用和保留期清理 |
| 恢复速度与安全约束 | 恢复形成新发布，重新核验当前有效限制 | 不能盲目恢复到取消了新禁飞限制的旧包 |

恢复时先核对五类对象与摘要，再验证来源、有效期及当前限制。事务失败维持旧指针，并不意味着旧包继续满足新的安全条件；如果收到已确认的限制而新发布暂时失败，部署服务应暂停受影响的新推荐，直到完成核验。该业务暂停与外部消息、身份服务的联合验收交由 LJ 的运行方案补充。

沿用 LQ 的课程模拟保留策略，发布与关联审计保留至验收完成并加30日复核窗口。清理必须排除当前发布、在用查询和保留范围内历史的引用。原型通过禁止删除保留所有对象；引用计数、实际清理、异地恢复及持续可用性属于后续部署验收。

## 6 已验证范围与技术决定

本模块使用Python标准库和SQLite本地事务实现可复核原型。SQLite允许多个读事务、单个写事务，WAL模式支持读写并行，适合演示提交前不可见及旧读者保持快照的行为。[4][5] 本次运行结果包括20项发布测试、19项LQ回归及21项ZC回归，详细证据见[评估记录](evaluation.md)。PostgreSQL方案的锁粒度、吞吐量和跨机恢复需在对应环境另行验证。

| 编号 | 采用的决定 | 依据与证据 |
| --- | --- | --- |
| ZQO-D1 | 五类不可变组件加独立发布编号 | 对齐ZC接口，同号改内容和混版输入拒绝测试 |
| ZQO-D2 | 原子指针、基线比较、请求幂等 | 并发发布、失败注入、重复请求测试 |
| ZQO-D3 | 查询固定版本，返回前核对权威目录 | 旧查询跨发布保持版本且变为过时，新查询读取新包 |
| ZQO-D4 | 业务、审计与待发送事件同事务 | 审计实际写入错误、提交前异常回滚测试 |
| ZQO-D5 | LQ派生风险绑定任务窗 | 跨窗复用与缺失窗口标记拒绝测试 |
| ZQO-D6 | 小场景全量重规划，保留完整历史 | 禁飞新增与撤销联合场景、重启重放测试 |

以上决定在本模块采用，保持 `starter-v0` 的空间、时间、风险和查询状态含义。总体关系见[架构与数据流](architecture.md)，实际模块接入情况见[集成说明](integration.md)。
