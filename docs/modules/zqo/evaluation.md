# 验证结果与设计取舍

## 执行条件

本次采用Python标准库SQLite文件数据库，启用WAL，使用多个独立连接和线程屏障控制读写交错。场景复用ZC的100×100米合成城市、10米网格和三维建筑，风险采用LQ的时段编译。任务窗固定为2026年11月4日00:00至00:10 UTC，运行时间、Python与SQLite版本、源码摘要保存在 [evaluation.json](results/evaluation.json)。

## 测试结果

| 验证组 | 已执行判据 | 结果 |
| --- | --- | --- |
| 发布原子性 | 对象写入后、审计后、提交前注入失败；另用数据库触发器制造真实审计写入错误 | 目录、发布、审计与待发送事件均无部分提交 |
| 读写交错 | 写者暂停在提交前，另一连接读取；提交后旧查询继续使用固定包 | 提交前只见旧发布；旧查询保留版本并标记过时 |
| 两个发布者 | 两个线程同时基于同一父版本发布 | 一个成功，一个返回基线过期 |
| 重试与不可变性 | 重复请求、同请求不同内容、同组件编号改内容、直接修改历史 | 重试不重复发布，冲突与改写被拒绝 |
| 恢复与通知 | 重开数据库、读取历史、保留待发送事件、处理重复及乱序提示 | 历史可重放，通知核对不倒退 |
| 跨模块条件 | LQ时间窗、版本匹配、缺失数据、审核职责、ZC的撤销和到期判断 | 条件不符拒绝或返回未知，撤销后重新规划 |

ZQO共20项测试通过，原有LQ的19项与ZC的21项回归全部通过，共60项。测试中有些方法包含多个失败点或边界子情境，60指测试方法数。原型没有部署PostgreSQL或消息中间件，因此这些结果支持本地事务目录及现有模块组合的行为。

## 三模块联合场景

固定风险权重λ=0，先用LQ风险输入发布v1。随后新增三维禁飞体 `[45,55]×[35,65]×[0,100]` 并发布v2，最后发布撤销记录v3。三次查询的几何、网格、速度和风险参数保持一致。

| 阶段 | 查询表现 | 航程 |
| --- | --- | --- |
| 初始v1 | 固定完整发布，路线可行 | 116.57米 |
| v2发布后仍完成的v1查询 | 仍引用v1，标记已过时 | 116.57米，作为历史结果保留 |
| 新查询使用v2 | 原路线2段受禁飞影响，新路线成功绕行 | 129.28米 |
| 发布v3撤销限制 | 重新搜索得到较短路线 | 116.57米 |

另在v2之后注入提交前失败，当前指针仍为v2，发布、审计与待发送事件数量不变。此次只改变空域，其他四类版本复用已有对象。完整路径、五类版本、来源与每段检查结果保存在原始JSON中。

实验显示“固定快照可行”和“当前可采用”需要分别表达。旧查询能稳定完成，但更新后必须重新核对。测试也验证了撤销触发重新搜索的必要性：只检查旧绕行路线仍可用，会保留一条已经不再最短的路线。

## 尚需部署环境验证的指标

| 指标 | 测量办法 |
| --- | --- |
| 更新可见延迟 | 从数据库确认提交，到使用新发布完成查询的时间；单独记录接入、构图和搜索部分 |
| 并发发布冲突 | 固定输入和发布速率，记录基线冲突、重试和等待，比较行锁方案 |
| 消息恢复 | 提交后停止投递进程并重启，检查重复处理和通知积压清空时间 |
| 运行恢复 | 注入进程退出、存储不可用及备份恢复，核对目录、对象、审计及引用 |
| 多时间窗风险 | 相同源发布、不同任务窗重新编译，比较风险状态与缓存命中 |

本次记录功能与一致性证据，不据单机测试时长推断线上吞吐量。真实鉴权、外部审计、业务暂停与跨机恢复由后续实际部署及LJ验收补充。

## 复现

在仓库根目录执行：

```sh
python3 docs/modules/zqo/prototype/evaluate.py
```

命令运行三个模块的测试，再生成本模块结果文件，不覆盖LQ/ZC的历史结果。只运行发布测试可执行 `python3 -m unittest discover -s docs/modules/zqo/prototype -v`。
