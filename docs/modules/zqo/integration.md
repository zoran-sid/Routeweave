## 可直接调用的接口

| 接口 | 输入和输出 | 使用规则 |
| --- | --- | --- |
| `prepare_risk`（风险准备） | ZC快照、查询、LQ时段列表；返回新快照和查询 | 增加 `compiled_window`（编译时间窗）并重新绑定版本 |
| `Catalog.publish`（事务发布） | 候选快照、验证查询、预期发布、请求编号、审核信息；返回发布编号 | 独立审核、输入有效、相同版本内容一致才可提交 |
| `Catalog.pin`（固定发布） | 当前或历史发布编号；返回完整发布包与来源时间 | 默认只读已提交包，摘要和组件一致性校验失败时拒绝 |
| `Catalog.query`（Q1查询） | 任务和可选固定包；返回ZC结果及发布新鲜度 | 将任务绑定所选包，不信任外部请求自带版本；历史读取由受控调用选择 |
| `Catalog.status`（Q2航段状态） | 任务、三维航段、可选历史发布；返回状态及限制来源 | 复用完整航段检查，暂不提供区域聚合或HTTP接口 |
| `consume_notification`（通知核对） | 上次版本、通知提示；返回权威目录中的新版本编号 | 通知内容不直接改写当前指针，允许重复和乱序提示 |

新增 `release_id`（发布编号）、`observed_head`（核对时的当前编号）、`freshness`（新鲜度）和 `checked_at`（核对时间），保留原五类版本。`feasible`（可行）与 `stale`（已过时）可以同时出现：前者描述固定输入下的可行性，后者说明它已不是当前推荐依据。

LQ原函数对调用窗口编译风险，但原输出没有窗口标记。本模块包装它而不改写LQ源码。检测到已有 `profile_inputs`（原始暴露时段）却没有编译窗口时，拒绝发布或查询。跨窗口服务需重新编译并发布匹配输入；原型不把不同窗口的派生风险混在同一个包中。

## LJ可复用的验收判据

- 发布未提交时，另一个连接只能看到旧发布。
- 发布对象、审计或提交前失败时，发布、当前指针、审计和待发送事件没有部分成功。
- 两个发布者基于同一版本提交时，一个成功，另一个因基线过期重新准备。
- 数据库重开后，历史发布仍可读取，待发送事件仍存在。
- 查询完成后若发布已变更，结果带旧版本和过时标记；新推荐重新计算。
- 外部通知丢失时，查询仍直接核对权威目录；实际消息投递延迟、鉴权、监控告警及服务暂停另行验收。

## 实施边界与后续替换

原型使用SQLite文件、独立连接和线程控制交错。真实PostgreSQL目录、身份服务、外部审计存储、消息投递与跨机故障恢复仍是设计项。采用新存储时复用本模块测试情境，特别核对事务提交、同号改内容、发布基线与结果过时的含义。任何版本清理需遵守在用与历史引用，当前原型保留全部发布。
