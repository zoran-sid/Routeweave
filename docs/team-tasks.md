# SkyRoute v2 五人任务安排

更新日期：2026-11-06（Asia/Hong_Kong）。分支：`develop`。v1 交付保留在 `main`（标签 `v1.0-algorithm-baseline`）。

## 1 为什么重组

课程题目是《面向真实场景的新一代数据管理系统设计》（[课程要求](course-requirements.md) PDF第1页）。PDF第4–5页的报告结构按数据管理层次组织：需求与数据、架构、数据模型、技术选型、治理、评估；第6页评分看问题定义、设计依据、技术判断与反思。

v1 按业务领域分工（空域、风险、三维数据、算法、运维），主线变成了航线算法：

| v1 现状 | 与课程的偏差 |
| --- | --- |
| 报告第6节整节讲风险公式与 A*/Dijkstra/D* Lite | 不对应课程任何一章 |
| PPT 第5、7、8页讲风险代理与搜索节点数 | 10页中3页是算法与风险建模 |
| 新兴技术为自定义的“版本化图投影” | 不在课程第3–4页的技术列表中 |
| 数据接入与集成、高可用与灾备、成本、部署 | 课程第2页要求，v1 只零散提及 |
| AI 辅助数据治理 | 课程第1页鼓励，v1 未涉及 |

## 2 v2 定位

**SkyRoute：面向城市无人机配送的时空数据管理平台设计**
（SkyRoute: A Spatio-temporal Data Management Platform for Urban UAV Delivery）

问题：城市三维环境、动态空域限制和地面暴露三类数据来源不同、更新频率不同、敏感程度不同。平台要管理它们的接入、版本、质量、血缘与权限，使每次查询都基于一致、可追溯的数据快照。

- **航线规划是下游查询负载**：Q1 三维航线查询、Q2 航段/区域状态与来源查询保留，算法只作为查询执行策略出现。
- **新兴技术**：主讨论“湖仓表格式的快照与时间旅行（Apache Iceberg 类）+ 数据血缘标准（OpenLineage 类）”，承接 v1 的“查询绑定发布版本”设计；次讨论“空间数据库 vs 图数据库”用于路径类查询。两者都在课程第4页列表内。
- **v1 成果的去向**：合成场景、原型和131项测试保留，作为课程第6页所说的加分佐证；报告与PPT的主线改为数据管理设计。

## 5 各成员任务

每人在 `docs/modules/<缩写小写>/v2/` 下交付：`section.md`（报告章节草稿，含图表与引用编号）、`slides.md`（两页展示文字与讲稿）、`references.md`（本章引用）。v1 模块文件保留为证据，不需要改写。

### ZQO：问题定义、总体架构与版本一致性

1. 摘要与第1章：从“数据管理问题”写起，说明为什么三类数据的版本与一致性是核心难点，四类用户分别得到什么价值。
2. 分层架构图与数据流图：批量 GIS/三维数据接入、空域更新的流式接入（CDC 或消息队列）、原始/清洗/发布三层存储、查询服务、消费端。
3. 新兴技术主讨论：湖仓表格式的快照与时间旅行如何实现“查询绑定发布版本”，与 v1 原子发布原型的对应关系；何时不适用（小数据量、低更新频率时的复杂度和成本）及替代方案（PostgreSQL 时态表/双时态模型）。
4. 权衡：**一致性 vs 可用性**——空域发布期间读取旧快照还是阻塞查询。
5. PPT 第1页回答“解决什么问题、为谁、价值”，第2页给架构与新兴技术；面向管理者和投资者。

复用：[ZQO 模块](modules/zqo/README.md)的空域生命周期、原子发布与架构图。

### YHT：需求与数据分析、数据模型与数据库设计

1. 第2章：功能需求（Q1/Q2、空域维护、审计）与非功能需求（延迟、新鲜度、可用性、合规）表；三类数据的来源、格式、更新频率、规模与3年增长估算（标注假设）；生命周期与访问模式。
2. 第4章：ER 图与关系模式；三维空间索引（PostGIS/R*Tree）；按空间瓦片与时间分区；冷热分层与归档；Q1/Q2 各一条典型 SQL 及执行思路。
3. **最先交付数据字典**（实体、字段、类型、来源、敏感级别），供 ZQO 架构、LQ 分类、ZC 选型、LJ 成本估算使用。
4. 权衡：**灵活模式 vs 数据质量**——多源 GIS 数据 schema-on-read 接入与严格模式校验。
5. PPT 第3页讲数据挑战，第4页讲数据模型与索引（可复用 v1 R*Tree 实测表）。

复用：[YHT 模块](modules/yht/README.md)的三维数据模型、存储说明和索引基准。

### LQ：数据治理、安全、隐私与伦理

1. 数据质量规则与质量门禁（复用 v1 门禁实测）；元数据目录字段；从源数据到查询结果的血缘图。
2. 身份认证与访问控制（RBAC/ABAC，按四类用户和敏感级别）；传输与静态加密；审计日志内容与保留期。
3. 隐私与合规：人口暴露数据的聚合粒度、去标识化，差分隐私的适用性与代价；配送轨迹的最小化与保留期。
4. **AI 辅助治理**（课程第1页鼓励）：源数据更新的异常检测、敏感字段自动分类，说明适用条件、误报漏报风险和人工复核。
5. 伦理：风险规避使飞行负担转移到特定街区的公平性问题。
6. 风险模型压缩为“风险层是带模型版本的派生数据集”，公式移到附录。
7. 权衡：**数据共享价值 vs 隐私保护**——暴露数据的空间粒度。
8. PPT 第5页讲质量、元数据与血缘，第6页讲安全、隐私与伦理。

复用：[LQ 模块](modules/lq/README.md)的质量门禁、来源追溯与职责分离模拟。

### ZC：技术选型论证、查询服务与性能评估

1. 第5章技术比较矩阵：PostgreSQL+PostGIS、SQLite R*Tree、图数据库（Neo4j 类）、PostGIS+pgRouting、内存图投影；评价维度为空间查询能力、路径查询能力、事务与一致性、扩展性、可维护性、成本；给出最终选型与理由。
2. 查询服务设计：Q1/Q2 接口字段（复用 v1 接口）、按数据版本的结果缓存与失效、物化图投影的重建与增量更新条件。
3. 第7.1节评估指标表：查询延迟（P50/P95）、吞吐量、数据新鲜度（发布→可查询）、规模扩展（建筑数、网格规模）、重建 vs 增量成本；每项给目标值、测试方法、已有证据或待做实验。
4. A*/Dijkstra 对照压缩为一张“执行策略改变访问代价”的佐证图，算法细节放附录。
5. 权衡：**预计算/物化 vs 数据新鲜度**——物化图投影与按需构图。
6. PPT 第7页讲选型比较与优势，第8页讲如何评估设计是否成功。
7. 整合与发布：汇编第8章、参考文献与附录；组装 `docs/final/` 的 v2 报告与 PPT；管理 `develop` → `main` 发布。

复用：[ZC 模块](modules/zc/README.md)的原型、Q1/Q2 接口与基准数据。

### LJ：部署、高可用、灾备与成本；权衡汇总

1. 第3.4节：云/边/本地部署策略；主从复制与故障切换；RPO/RTO 目标；备份与恢复演练（复用 v1 恢复原型）。
2. 数据可观测性与 SLO：新鲜度、完整性、查询错误率的监控与告警，与 ZC 指标表对齐。
3. 第7.2节成本模型：按 YHT 规模估算的存储分层与计算成本，说明主要成本驱动项。
4. 第7.3节：汇总五人的权衡表（课程第6页要求至少两项），风险、局限与改进方向。
5. 权衡：**实时性 vs 成本**——流式更新与热存储对比批量更新与冷存储。
6. PPT 第9页讲高可用、灾备与成本，第10页讲权衡、局限与结论。

复用：[LJ 模块](modules/lj/README.md)的监控、异常处理、恢复原型与验收情境。
